Proposed next TV commands:

```sh
ps -eo pid,comm
ls -l /dev/dri/card0 /dev/fb0 /dev/fb1

for p in /proc/[0-9]*; do
    hits=$(readlink "$p"/fd/* 2>/dev/null |
        grep -E '^/dev/(dri/[^/]+|fb[0-9]+|mali[0-9]*)$')

```

These inspect process names and device links without dumping process arguments or environments. Device ownership narrows the investigation; it does not prove an available client protocol, acceleration or safe display takeover. **1. Fullscreen custom shell; retain vendor kernel, services and compositor**

**Delivered capability:** a remote-operated home screen, input selection, status, settings and selected applications running inside the TV. Vendor components continue handling panel timing, HDMI receiver/HDCP, audio, standby and thermal behavior.

This must deliver an everyday environment: dependable entry, navigation, HDMI return, volume/power controls and escape to stock UI. Installing Homebrew or displaying a static fullscreen page is insufficient.

**Evidence needed:** actual compositor/client protocol; supported fullscreen and input behavior; compatible graphics libraries; narrowly identified control interfaces; behavior when HDMI video appears; startup/persistence mechanism; resource headroom.

**Next read-only TV commands**, after the ownership check:

```sh
for f in /usr/lib/libEGL.so* /usr/lib/libGLESv2.so* \
         /usr/lib/libwayland-client.so* /usr/lib/libgbm.so*; do
    [ -e "$f" ] && ls -l "$f"
done

for s in /run/wayland-* /tmp/wayland-*; do
    [ -S "$s" ] && ls -l "$s"
done

grep -E '^(MemAvailable|MemFree|SwapTotal|SwapFree):' /proc/meminfo
```

Socket/library absence at these paths is inconclusive. Follow discovered process and package paths rather than guessing endpoints. Do not invoke unknown service methods merely because their names look like queries.

**Risk/reversibility:** lowest relative risk, but a fullscreen client can consume memory, capture remote input or obstruct stock controls. Persistent autostart can create a recurring failure. Prefer a later, owner-notified manual launch before considering persistence.

**Go gate:** an evidenced client route, explicit retained/replaced ledger, stock escape mechanism and independently usable administrative access. A later bounded test must demonstrate HDMI input, protected playback, audio, remote and power preservation. **No-go** if basic operation requires stopping essential vendor services or changing system partitions.

**2. Alternative Linux userland/chroot; prefer stock compositor, then investigate DRM/fbdev**

**Delivered capability:** a substantially different native software environment and application set sharing the stock kernel. A chroot changes filesystem/userland context; it supplies neither graphics integration nor hardware control by itself.

**Evidence needed:** executable ABI and loader; libc/kernel compatibility; compatible graphics client stack; storage and memory budget; vendor-service integration; isolation boundaries. Cortex-A55-class hardware does not establish that an arm64 userland will run under this armv7l kernel.

**Next read-only TV commands:**

```sh
command -v readelf file chroot unshare
readelf -h /bin/busybox
readelf -l /bin/busybox | grep 'interpreter'
cat /proc/filesystems
cat /proc/self/cgroup
df -k /home /media /tmp

for f in /sys/class/graphics/fb[01]/name \
         /sys/class/graphics/fb[01]/virtual_size \
         /sys/class/graphics/fb[01]/bits_per_pixel; do
    [ -r "$f" ] && printf '%s: ' "$f" && cat "$f"
done
```

`readelf` is conditional on availability; an absent interpreter entry may simply indicate a static executable. These commands do not launch a chroot or open display devices for rendering.

**Risk/reversibility:** memory pressure and kernel incompatibilities; shared-kernel effects; excessive device exposure; framebuffer/display contention. Preserve vendor ownership initially. Direct DRM/fbdev rendering is a separate experiment requiring its own evidence and owner notice.

**Go gate:** viable 32-bit ABI, bounded resources, explicit device/service access and cleanup, plus a demonstrated display-client route. **No-go** for direct scanout until ownership, supported modes and restoration are characterized. No modesetting, framebuffer writes or device ioctls are proposed in this read-only phase.

**Evidence needed:** compositor identity; supervisor and dependencies; graphics-buffer ABI; vendor video-plane integration; remote handling; watchdog behavior; a restoration mechanism that works with a black screen.

**4. Custom boot/kernel, only after characterization**

**Delivered capability:** alternate init/rootfs and potentially a rebuilt kernel—the strongest replacement boundary, with the largest hardware-integration burden.

**Evidence needed:** exact running configuration and board association; boot acceptance policy; complete compatible BSP/build inputs; panel/HDMI-IN/audio/power dependencies; image packaging; documented boot route; independent recovery and unit-data preservation.

Existing source evidence is useful but incomplete: vendor driver trees exist, while packaging inputs and adaptation coverage remain unresolved. The libkadaptor inspection stopped partially; unread content cannot be classified as absent.

**Next read-only TV commands:**

```sh
if [ -r /proc/config.gz ]; then
    zcat /proc/config.gz |
        grep -E '^(CONFIG_(ARM|ARM64|MODULES|MODVERSIONS|KEXEC|IKCONFIG|IKCONFIG_PROC|DRM|FB|TEE)=|# CONFIG_(KEXEC|MODVERSIONS) is not set)'

for n in 27 38; do
```

These establish configuration/layout facts only. `KEXEC` availability would not authorize or prove a safe alternate boot; partition `ro` attributes do not establish signature enforcement. Do not read raw boot/system partitions, OTP, RPMB or provisioning stores in this phase.

**Risk/reversibility:** boot failure, loss of display/power control, unit-data damage and dependence on unavailable recovery.

**Go gate:** verified exact-target route **plus independent operation-specific recovery plus an explicit owner decision**, alongside hardware safety and preservation evidence. [Recovery remains unproven](/workspace/lg-tv/tvs/lg-65nano756pr/evidence/recovery-case.md:10). This review proposes no boot, flash or system-partition writes.

**Staged sequence and acceptance**

1. Resolve display ownership, client ABI and supervisor relationships using targeted reads.
2. Define route 1’s retained/replaced ledger and manual escape behavior.
3. Prepare a concrete, bounded prototype proposal off-TV. Give owner notice before every non-read-only TV action, including copying files, installing software, launching a UI, changing hooks or restarting services.
4. In a separately authorized test, verify the existing operating profile: panel/backlight, HDMI **input**, normal protected AppleTV playback, audio/mute/volume, remote/input control, CEC and standby/wake. Add no new modes or calibration changes.
5. Consider route 2 if it adds needed capability. Escalate to routes 3–4 only when their specific gates pass.

No writes to kernel, rootfs, tvservice, boot or system partitions; no flashing or exploit reproduction. Factory reset, ordinary stock updating and parallel partitions remain insufficient substitutes for independent recovery.
