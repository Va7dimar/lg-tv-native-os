#### Minor (Nice to Have)

1. **Exact-cap status is fail-closed “exceeded”** (`Budgets.exhausted`, lines 131-138, uses `>=`; checked at the top of the member loop, lines 472-477). Probe `exact_member_cap_complete_archive`: a two-file archive with `max_members=2` finished both members, then marked `status=partial` / `max_members exceeded`. That is not a ceiling relaxation (it is stricter than “exceed”) and cannot produce a false `ok=true`. It can falsely label a complete-at-exactly-N run as partial. Catalog defaults (200000 / 100000000 / 20 GiB) make an exact landing after the last member of the last archive unlikely. Optional fix: treat equality as allowed and only stop when the *next* member would exceed, or call `next()` before the equality check so a trailing `None` can complete cleanly.

2. **Expansion-overflow member bookkeeping.** When a file would exceed the expanded budget, the code appends a descriptive member (`reasons` include `max_expanded_bytes`) and breaks without incrementing `budgets.members` (lines 567-590). The archive’s `members` list / `member_count` can therefore exceed `totals.member_count`. Harmless for fail-closed budgeting; slightly confusing for consumers.

3. **Dead helper** `_pax_records_valid` (lines 741-765) is no longer called (stdlib still fail-closes malformed PAX inside `next()`). Safe leftover.

4. **`tooling/README.md` is stale in two places:** it still says tests should report `Ran 48 tests`, and the isolated-invocation example still passes `--min-free-disk-bytes 1`, which the CLI now rejects. The later README paragraph correctly states the 10 GiB floor.

5. **Launcher TOCTOU is smaller but not gone.** After a successful nofollow open+close, `path.resolve()` is used for the bind source (`isolate_inventory.py:84-90`). A leaf cannot be a symlink at check time; a replacement race between close and bind remains a local-attacker residual, not an archive-content issue.

### Compensating controls vs impossible guarantees

These are **not** must-fix defects. They are the real limits of this design and must travel with any checkpoint “pass”:

- **noexec output/stage is not demonstrated** and remains `false` in both `controls` and `isolation_observation`. bwrap tmpfs and the output bind can execute files. Compensating controls: the tool never executes members, never chmods selected files executable, and writes selected text as mode `0644` untrusted NUL-free data. A later human or other tool could still run those files.
- **`prlimit --as` is virtual address space (VSZ), not RSS / cgroup `memory.max`.** It can stop large parser allocations and can also kill a legitimate Python+gzip VSZ. It is not a working-set guarantee.
- **CPython `tarfile.next()` reads PAX/GNU extended-header payloads before semantic pathname/member budgets run.** Semantic caps cannot contain that allocation. The approved backstop is mandatory `isolate_inventory.py`: 1 GiB AS + 120 s `timeout --kill-after=5s` / `prlimit --cpu`. Direct `inventory_archives()` / bare CLI is for tests and trusted fixtures only.
- **Disk reserve is observed once before work**, not reserved by the filesystem. Heavy `--select` can still hit `ENOSPC` afterward; `selected_write` fail-closes. There is still no separate selected-text aggregate cap below the 20 GiB expansion budget.
- **In-process wall checks** run between members and during payload reads (`_consume_payload`, lines 411-413). Time inside `tarfile.next()` still depends on the process wall.
- This tool still does **not** establish a BSP, boot route, recovery path, or replacement OS.

### Checkpoint scope (isolated metadata + selected text)

A later worker may run `isolate_inventory.py` against the three already-downloaded catalog originals (read-only inputs, explicit output dir, optional `--select` of safe plaintext, optional `--hash-input` to compare with `evidence/catalog-manifest.json`) **without raising any hard ceiling**.

**Strong guarantees (actually implemented):**
- Leaf symlink / non-regular inputs rejected (`O_NOFOLLOW`).
- Duplicate input paths and basenames rejected.
- Aggregate member, pathname/metadata, and logical-expanded budgets shared across the three inputs; breach or policy/parse `failed`/`partial` stops the run and skips later inputs.
- Archive members classified with path/link/type policy; links never followed; nested archives not expanded; devices/FIFOs/unsupported types fail the run.
- Selected copies only for accepted regular NUL-free members at or under 16 MiB, written under `output/selected/<archive-basename>/` with `O_CREAT|O_EXCL` and mode `0644`, contained after resolve.
- Inventory JSON/Markdown replaced via temp + fsync + `os.replace`; `ok=true` only when `status==ok`.
- Isolated process: `timeout` + `prlimit --as=1GiB` + `bwrap --unshare-all` (no `--share-net`), no `/home` `/root` `/cursor` binds, ro inputs, writable output only.
- `--hash-input` digests the raw input bytes (verified on a synthetic `.tar.gz`).

**Limitations that travel with a pass:** see compensating controls above. Do not describe the output directory as noexec. Do not treat semantic caps as a memory sandbox. Do not treat a successful inventory as hardware or OS progress.
